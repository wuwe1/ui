# 完成度

每个组件做完都要过这一份。affectUI 最值得学的就是这个：每个组件的状态、动效、键盘、无障碍都想到了，文档短而具体。这里把它写成规矩，再补上它没做的（主题、中文、只吃数据）。做组件的流程在 `.claude/skills/component/SKILL.md`。

## 承载什么

先写清楚这个组件替用户做了什么事（一两句），再画。画出来的每个元素都要能对上其中一件事；对不上的不要。

## 状态

- 列全：默认、空、加载中、出错、内容很长（截断还是换行）、条目很多（滚动、分页）、禁用、只读、实时变化（数字在变、条目进出、换位置）
- 每一种在展示页（`showcase/stories.tsx`）里有一个，名字和组件文档的 States 对得上
- 加载中画轮廓（`Skeleton`），和加载好的样子一样高，加载完不跳；空的用 `Placeholder`，说清这里会出现什么、能做什么

## 键盘

- 能点的都能 Tab 到，顺序和看到的一样；`Enter` / `Space` 触发；`Esc` 关掉浮层，焦点回到打开它的地方
- 一组同类的东西（列表、tab、菜单）：Tab 进来一次，上下 / 左右键在里面走，`Home` / `End` 到头尾
- 全局快捷键（`⌘↵` 允许）只给最该接的那一个；焦点在有字的输入框里、开着对话框时不接；按钮上用 `Kbd` 写出来（手机上不显示）
- 焦点看得见：`focus-visible` 时有环，鼠标点的不出环

## 无障碍

- 对比度由主题保证（`docs/theme.md`）：有固定意思的颜色当字用一律 `-strong`
- 颜色不是唯一的信息：状态点旁边有字或 `title`，出错除了红还有字
- 读屏：能点的都有名字（只有图标的按钮写 `aria-label`）；状态变了用 `role="status"` 读出来；会走的钟 `aria-hidden`
- 不嵌套可点的东西（按钮里不放按钮）
- 手机上能点的地方至少 44px 高

## 动效（motion）

- 只给有意义的变化：出现、消失、换位置、数字变。不为好看而动
- 时长：小的（徽标、提示）150ms，一般的 200ms，大的（抽屉、Sheet）300ms 以内
- 缓动：出现用 `ease-out-strong`（先快后慢），消失用 `ease-in-strong`（干脆），跟着手指的用 `ease-drawer`（松手后接着速度滑到位）
- 换位置的过去（transform），不瞬移；数字用 `tabular-nums`，变的时候宽度不抖
- 跟手：拖的时候每帧跟着手指（不经过 React 重画），松手从看到的位置动画到底
- `prefers-reduced-motion`：移动、缩放换成淡入淡出或直接到位，但不能丢信息（扩散的状态点停成外面一圈淡的）

## 响应式

- 三档：手机（< 768px）、平板（768–1023）、电脑（≥ 1024）
- 手机上浮层改成从下面出来的 Sheet（`Popsheet`），侧栏、面板是跟手的抽屉
- 内容不撑破容器：长代码横着滚，宽表换成一行一张卡片，标题截断时右边的状态不被挤掉

## 只吃数据

组件只认 props（数据）和回调，不去拿接口、不读全局状态。项目自己把数据接进来（mixer 的 `InboxHome` 接 `Inbox`）。这样同一个组件各项目都能用，展示页也能用假数据把每种状态摆出来。

## 文档

每个组件一份 `docs/components/<组件>.md`，小节：承载什么 / Anatomy / States / When to use / When not to use / Accessibility / Motion / Responsive / Notes for AI。每条写具体行为（哪个元素、什么情况、怎么样），不写形容词。
